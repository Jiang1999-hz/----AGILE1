# AI Tutor PRD

适配当前项目的讲题对话模块产品需求文档。

基于外部草稿版 PRD 整理，并按当前项目实际情况做了三项关键调整：

1. 不采用前端直连 Ollama，统一改成后端代理。
2. System Prompt 不只注入题目和答案，还必须注入标准解答与当前追问点。
3. AI 的核心定位不是“通用数学聊天”，而是“围绕当前题目与标准解答的私塾讲题 AI”。

## 1. 产品定位

AI Tutor 是学生做完题后，出现在结果页右侧的讲题对话模块。

它的目标不是代替题库标准解答，也不是自由聊天，而是：

- 帮学生看懂当前这道题
- 帮学生理解标准解答中的某一步
- 在学生追问时换一种更简单的方式继续讲
- 始终围绕当前题目，不跳题、不跑题

## 2. 当前项目中的位置

挂载位置：

- 学生做完 5 道题后的结果页右侧

依赖上下文：

- 当前选中的题目
- 学生答案
- 标准答案
- 标准解答摘要
- 之后会继续补的分步解答

第一阶段不做：

- 通用 AI 聊天页替换
- 教师端 AI 助手
- 历史会话持久化
- TTS

## 3. 用户场景

### 场景 A

学生点开一道错题，右侧面板自动出现开场消息：

- 我可以围绕这道题继续讲
- 你可以问某一步为什么这样做
- 也可以让我先解释知识点

### 场景 B

学生点击快捷按钮：

- 这一步为什么这么做？

AI 基于当前题目和标准解答，对关键步骤做解释。

### 场景 C

学生输入：

- 我还是不懂
- 能不能更简单一点
- 为什么这里要这样变形

AI 不重新讲整道题，而是围绕学生卡住的地方继续解释。

## 4. 设计原则

### 原则 1：标准解答优先

学生先看标准解答，AI 负责补充说明，不负责另起一套完全不同的主解法。

### 原则 2：强上下文绑定

AI 每次回答都必须绑定当前选中的题目，不能变成通用聊天机器人。

### 原则 3：像老师，不像模型

回答要自然、清楚、像老师讲题，不要出现程序员味很重的格式或模板话术。

### 原则 4：优先讲明白，再讲高级渲染

第一阶段先把内容讲清楚。公式渲染和图示可以有，但不作为第一优先级。

## 5. 架构方案

### 5.1 推荐链路

统一采用：

```text
前端结果页
  -> 项目后端 API
  -> Ollama
  -> 项目后端整理响应
  -> 前端流式显示
```

不采用：

```text
前端 -> 直接请求 Ollama
```

### 5.2 为什么必须走后端代理

- 前端不直接暴露模型地址和细节
- 方便以后切换模型，不改前端
- 方便统一控制 prompt、超时、日志和错误处理
- 后续能做权限、审计和策略收口

## 6. 后端接口设计

建议新增接口：

```text
POST /api/student/1/quiz-followup
POST /api/student/1/quiz-followup-stream
```

### 6.1 请求体

```json
{
  "question": {
    "id": "sequence-014",
    "question": "...题目 HTML 或纯文本整理版...",
    "studentAnswer": "12,1,6,5,48,60,13,12,13",
    "correctAnswer": "12,1,6,5,48,60,13,12,13",
    "explanation": {
      "summary": "标准解答摘要",
      "steps": []
    }
  },
  "conversation": [
    {
      "role": "user",
      "content": "这一步为什么这么做？"
    }
  ],
  "userMessage": "能不能更简单一点？"
}
```

### 6.2 后端职责

- 读取当前题目上下文
- 组织 System Prompt
- 控制对话历史长度
- 请求 Ollama
- 把流式结果转发给前端
- 在必要时做统一错误处理

## 7. Prompt 设计

### 7.1 System Prompt 必须包含

- 当前题目全文
- 学生答案
- 标准答案
- 标准解答摘要
- 分步解答（有就传）
- 当前追问内容
- 行为规则

### 7.2 核心规则

建议固定写进 System Prompt：

```text
你是一个私塾数学讲题 AI。
你只围绕当前这道题、学生答案、标准答案和标准解答来回答。
不要跳到别的题，不要扩展成泛泛聊天。
如果学生问某一步，就优先解释那一步。
如果学生说“还是不懂”，就换更简单的方式讲，不要只重复原话。
优先使用自然中文说明，必要时再使用简洁的数学公式。
```

### 7.3 不建议的做法

- 只传题目，不传标准解答
- 只传标准答案，不传学生答案
- 让模型自由发挥整套解法

## 8. 前端交互设计

右侧 AI 面板分三块：

- 顶部
  - `AI Tutor`
  - 当前状态标签
- 中部消息流
  - AI / 学生对话气泡
  - 支持滚动
- 底部交互区
  - 快捷按钮
  - 输入框
  - 发送按钮

### 8.1 快捷按钮

第一版保留这 4 个：

- 这一步为什么这么做？
- 能不能更简单一点？
- 先解释这个知识点
- 如果能画图就更好了

### 8.2 快捷按钮的真实作用

它们不是固定文本展示，而是快捷生成用户问题。

例如：

- 这一步为什么这么做？
  - 等价于发送当前追问
- 能不能更简单一点？
  - 等价于基于上一条 AI 回复继续追问

## 9. 流式输出

第一版保留流式输出方案，但通过后端转发。

### 9.1 前端体验

- 一边生成一边显示
- 输出过程中显示光标动效
- 结束后光标消失

### 9.2 第一版渲染范围

优先支持：

- 段落
- 列表
- 基础数学公式显示

先不把重心放在复杂数学排版和图形能力上。

## 10. 图示策略

“如果能画图就更好了”先作为保留按钮，但第一版不承诺复杂图形输出。

第一版允许：

- 简单结构化说明
- 简单 ASCII 示意
- 简短公式块

后续再考虑：

- Mermaid
- SVG
- 专门的数学图示渲染

## 11. 错误处理

### 11.1 错误类型

- Ollama 未启动
- 模型不存在
- 超时
- 流中断
- 后端内部错误

### 11.2 用户提示

- AI 服务未启动，请检查本地模型
- 当前模型不存在，请先拉取模型
- 响应超时，请稍后重试
- 连接中断，已保留部分回答

## 12. 配置项

统一放在后端环境变量中：

- `OLLAMA_BASE_URL`
- `OLLAMA_MODEL`
- `OLLAMA_TEMPERATURE`
- `CHAT_MAX_HISTORY`
- `CHAT_TIMEOUT_MS`

前端不直接读取这些配置。

## 13. 第一阶段开发范围

### P0

- 后端代理 Ollama
- 单题上下文注入
- 流式返回
- 4 个快捷按钮
- 输入框发送
- 基础错误处理

### P1

- 更强的标准解答 steps 支持
- 更自然的讲题 prompt
- 更好的公式渲染

### 暂不做

- 前端直连 Ollama
- 多模型切换给学生开放
- 对话持久化
- 语音播报

## 14. 开发前结论

这版 PRD 对当前项目的正式要求是：

- AI 讲题必须是结果页的一部分
- AI 讲题必须围绕题目与标准解答
- AI 接入必须通过项目后端代理 Ollama
- 第一版先做“讲明白”，再做“渲染得更花”

这将作为接下来正式重做 AI 模块的基线文档。
